Ensimmäisessä luettavassa artikkelissa (Niemi 2025) kuvattiin virtuaalipalvelimen vuokraamisen ja pystyttämisen vaiheet.

- kirjoittaja vuokrasi virtuaalipalvelimen UpCloudilta, hankkimisen eri vaiheet oli dokumentoitu kuvakaappauksin ja pohdittu eri vaihtoehtoja, mutta valittu lopulta halvimmat.
- Kirjautumismetodia varten kirjoittaja oli luonut jo etukäteen SSH-avainparin virtuaalilinuxissaan, julkinen avain piti kopioida ja liittää UpCloudin sivulle.
--> pystyyköhän tämän vaihtamaan myöhemmin vai pitääkö SSH-avainpari olla jo valmiina kun ottaa palvelinta?
- SSH-julkisen avaimen lisääminen oli viimeinen vaihe, pilvipalvelimen hankkiminen vaikutti verrattain helpolta toimenpiteeltä.

- alkutoimia varten kirjoittaja otti etäyhteyden virtuaalipalvelimeen komennolla ssh root@virtuaalipalvelimenIP (kirjoittajan mukaan juuri tehdyn IP-osoitteen löytää UpCloudin sivulta)
- tämän jälkeen kirjoittaja lisäsi sudo-käyttäjän, lisäsi tämän käyttäjän kotikansioon julkisen ssh-avaimen, sekä muokkasi ssh-avaimeen liittyvien kansioiden omistajuuksia ja käyttöoikeuksia. Käytetyt komennot:
adduser sudo [user]
mkdir -p /home/user/-ssh
chmod 700 /home/user/.ssh
nano /home/user/.ssh/authorized_keys (tänne lisätään public key)
chmod 600 /home/user/.ssh/authorized_keys
chown -R user:user /home/user/.ssh
- seuraavaksi kirjoittaja asensi palomuurin (Uncomplicated Firewall) ja avasi siihen portin 22 ssh-yhteyksille ennen palomuurin ottamista käyttöön. Käytetyt komennot:
apt-get update
apt-get install ufw
ufw allow 22/tcp
ufw enable
ufw status (tällä tarkistetaan palomuurin tila, active tarkoittaa että palomuuri on käytössä)
Kirjoittaja pääsi kirjautumaan uudella käyttäjällään user@pilviIP ilman ongelmia.
- tämän jälkeen kirjoittaja sulki vielä root-tilin, poisti sen mahdollisuuden kirjautua ssh:lla ja käynnisti palvelimen uudellen. Käytetyt komennot:
sudo usermod --lock root
sudoedit /etc/ssh/sshd_config --> PermitRootLogin No
sudo service ssh restart
- lopuksi kirjoittaja päivitti vielä web-palvelimen ottamalla ssh-yhteyden pilvipalvelimeen ja asentamalla apache2-daemonin. Kirjoittaja korvasi apachen oletustestisivun sanalla "laser" kurssinsa ohjeistuksen mukaisesti. Kirjoittaja päästi palomuurista läpi portin 80 liikenteen ja asensi lisäksi apachen automaattiset päivitykset, mutta ainakin hänelle jäi epäselväksi, menivätkö ne läpi. Lopuksi kirjoittaja käynnisti järjestelmän vielä uudelleen ja totesi, että sivu toimii. Käytetyt komennot:
sudo apt update
sudo apt-get install apache2
sudo nano /var/www/html/index.html 
sudo allow 80/tcp
sudo ufw enable
echo "laser" | sudo tee /var/www/html/index.html --> tällä saa sanan "laser" etusivulle
sudo apt-get update
sudo apt-get dist-upgrade (ainakin tässä kirjoittajalla oli raporttiinsa lipsahtanut mielestäni kirjoitusvirhe)
sudo apt-get install bash-completion
systemctl reboot

#### c) Alkutoimet. ####

Lisätty käyttäjä komennolla sudo adduser ansku. Jätetty muut kentät tyhjäksi painamalla toistuvasti enteriä. Lisätty käyttäjä sudo-ryhmään ja annettu oikeudet lukea lokeja ilman sudoa. Komennot sudo usermod -aG sudo ansku ja sudo usermod -aG adm ansku. (Heinonen 2025)
Tämän jälkeen tein kotihakemistoon kansion komennolla mkdir -p /home/ansku/.ssh, muutin oikeudet komennolla chmod 700 /home/ansku/.ssh, loin nano-tekstieditorilla tiedoston authorized_keys (nano /home/ansku/.ssh/authorized_keys) ja lisäsin sinne julkisen ssh-avaimen. Kopioin sen toisesta terminaali-ikkunasta virtuaalikoneen -ssh-kansiosta cat-komennolla. (Niemi 2025)
Asetin oikeudet ohjeiden mukaisilla komennoilla chmod 600 /home/ansku/.ssh/authorized_keys ja chown -R ansku:ansku /home/ansku/.ssh/. Ohjeisiin oli lipsahtanut pieni kirjoitusvirhe, tarkoituksena on asettaa oikeudet koko ajan samalle käyttäjänimelle. (Niemi 2025)
Kokeilin tässä vaiheessa kirjautua toisella terminaalilla ssh ansku@IP ja se onnistui, eli SSH toimii.

![ssh login](/kuvat/ssh-login.png)

Tämän jälkeen asensin palomuurin komennolla apt-get install ufw (sudoa ei tarvita eteen koska olen edelleen kirjautuneena rootina), tein reiän ssh-liikenteelle komennolla ufw allow 22/tcp ja käynnistin palomuurin komennolla ufw enable. Tarkistin lopuksi tilanteen komennolla ufw status verbose, jonka perusteella palomuurin on päällä ja se päästää ssh liikenteen sisään. Ohjeiden mukaisesti lukitsin rootin komennolla sudo usermod --lock root ja poistin rootilta mahdollisuuden kirjautua ssh:lla muokkaamalla sudoedit /etc/ssh/sshd_config -tiedoston kohtaa PermitRootLogin yes --> no. (Niemi 2025)

Aiemmalla kurssilla samaisesta tiedostosta on poistettu myös salasanakirjautuminen kohdasta PasswordAuthentication yes -> no, mutta jätin sen tällä kertaa paikoilleen. Muutosten ottaminen käyttöön edellyttää ssh-palvelimen uudelleenkäynnistystä, jonka tein komennolla sudo systemctl restart ssh. Olin vielä roikottanut root-käyttäjän terminaali-ikkunaa avoinna, mutta suljin sen pois.
